# SR-AttELM-H: методика адаптивного відновлення багатовимірних асинхронних даних

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/ALAXAY/sr-attelm-h/blob/main/notebooks/SR_AttELM_H_Colab.ipynb) [![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.22975925.svg)](https://doi.org/10.5281/zenodo.22975925)

Код до статті «A technique for adaptive reconstruction of asynchronously delivered sensor data using
availability-aware spatiotemporal attention and a sector-structured recurrent extreme learning machine»
(О. Д. Фесенко, стаття на розгляді в журналі Ad Hoc Networks).

## Призначення

Репозиторій призначено для відтворення експериментальної перевірки методики адаптивного відновлення
багатовимірних асинхронних даних на основі механізму просторово-часової уваги та рекурентної машини
екстремального навчання із секторним вихідним шаром. Оцінка вектора стану формується лише за повідомленнями,
які надійшли до моменту прийняття рішення. Вихідна матриця активного сектора уточнюється рекурсивним алгоритмом RLS
після надходження верифікованого значення.

## Склад репозиторію

| Папка | Призначення |
|---|---|
| `srattelm/` | протокол оцінки з двома часовими координатами повідомлення (час формування вимірювання та час надходження кожного компонента), етапи 1–7 і попередній етап методики, варіанти з почерговим виключенням складових, метод перенесення останнього доступного значення (LOCF) |
| `srattelm/agg/` | адаптер ядра Asynchronous Graph Generator (AGG) до того самого протоколу оцінки |
| `netsim/` | модель мережі моніторингу з переривчастою зв’язністю, реалізації мережевих затримок, статистика затримок і рис. 8 статті |
| `notebooks/` | блокнот Google Colab для відтворення експериментів |
| `data/` | місце для архіву набору даних Beijing Multi-Site Air Quality; набір даних у репозиторії не поширюється |

## Відповідність замороженому протоколу

Вихідний код конфігурації, замороженої для експериментів 1–4 статті, недоступний. Методику відтворено за її
описом у розділах 4 і 5 статті, і зазначене відтворення використано в розділі 7.8 (табл. 12 і 13 статті).
Кількість затриманих компонентів збігається точно, а RMSE методу LOCF збігається до четвертого знака в п’яти
запусках із шести, у шостому запуску розбіжність становить 0,0001 (табл. 1).

## Порядок запуску

Перший спосіб полягає у запуску блокнота `notebooks/SR_AttELM_H_Colab.ipynb` у середовищі Google Colab
(кнопка «Open in Colab» вище). Блокнот завантажує набір даних із репозиторію UCI, перевіряє контрольну суму
SHA-256 масиву даних і протокол оцінки, після чого виконує експерименти. Орієнтовна тривалість розрахунку без
ядра AGG на центральному процесорі Colab становить 40–60 хв.

Другий спосіб полягає у локальному запуску за наявності Python 3.10 або новішої версії:

```
pip install -r requirements.txt
curl -L -o data/beijing_multi_site_air_quality.zip https://archive.ics.uci.edu/static/public/501/beijing+multi+site+air+quality+data.zip
cd srattelm
python run_experiments.py        # методика, варіанти, LOCF; геометричні та мережеві затримки
python run_component_check.py    # табл. 13 статті
python agg/run_agg.py            # офіційне ядро AGG (20–25 хв на поділ і модель затримок, 12 потоків)
python summarize.py              # summary_network.csv, paired_network.csv (табл. 12 статті)
python summarize_components.py   # availability_check_summary.csv (табл. 13 статті)
cd ../netsim
python delay_statistics.py       # табл. 10, 11 статті та автокореляція затримок
python make_figure.py            # рис. 8 статті
```

Шлях до набору даних задається змінною середовища `SRATTELM_DATA` (архів будь-якого рівня вкладеності або
папка з файлами `PRSA_Data_*.csv`). Реалізації мережевих затримок входять до складу папки `netsim/`, а скрипти
`generate_delays.py` і `generate_training_delays.py` відтворюють їх побітово.

Результати, наведені в табл. 2, показали, що на мережевих затримках методика зменшила RMSE на 51,13 %
відносно LOCF і на 21,73 % відносно офіційного ядра AGG у шести з шести парних запусків.

Врахування параметрів доступності у вагових коефіцієнтах джерел зменшило RMSE на 10,28 % для геометричних і
на 15,49 % для мережевих затримок (табл. 3). Отриманий результат обумовлений тим, що без параметрів
доступності розподіл вагових коефіцієнтів джерел наближається до рівномірного.

## Обмеження

Перше обмеження пов’язане з відтворенням методики. Параметри, які в статті не наведено, задано заново, тому
зміна RMSE на 0,15 % для варіанта з просторовою увагою та величина зниження ентропії розподілу вагових
коефіцієнтів (табл. 8 статті) не відтворюються й належать до замороженої конфігурації.

Друге обмеження визначається даними. Використано один набір даних дванадцяти станцій моніторингу якості
повітря, час надходження повідомлень сформовано моделлю затримок, а координати станцій у моделі мережі задано
наближено (з точністю близько 1 км) і використано лише для визначення відстаней між вузлами.

Третє обмеження стосується порівняння з AGG. Ядро AGG навчається за графіком адаптера для окремих цілей
(7000 цілей, до 18 епох). Повний конвеєр навчання офіційного репозиторію не використовується.

Четверте обмеження пов’язане з обчислювальним середовищем. Результати отримано на центральному процесорі з
Python 3.12.14, PyTorch 2.13.0, NumPy 2.5.3 і pandas 3.0.6. На іншому обладнанні RMSE методики може
відрізнятися в четвертому знаку, тоді як кількість затриманих компонентів збігається точно.
Роботу на графічному процесорі не перевірено.
